## Deviations from the Python code (all deliberate)
1. Depth `h` is an explicit argument of `search`; `termination_by k - h`, proved automatically from the guard `b[w] + h < k` (hence h < k).
2. Cascade `while queue:` is a bounded loop `for i in List.range n` over a FIFO array with read index `i`. That n iterations suffice is a proof obligation (each node enqueued at most once per cascade; the origin v is on the stack). A cutoff would make the Lean code diverge from Python. **Discharged** in `Bsdfs/Cascade.lean`: the queue's nodes are distinct (`CascCore.nodup`), so it has at most n entries and every entry is processed (`casc_break`, `casc_final`).
3. `pred` is stored explicitly to reproduce NetworkX scan order; `Graph.WF` (pred is the reverse of succ, both Nodup) is assumed by the completeness and delay theorems.

## Theorem statements
- `bsdfs_sound` (s ≠ t): every output is a simple s-t path with at most k edges. **Proved** in `Bsdfs/Sound.lean` (statement unchanged, removed from `BsdfsExec.lean`); `#print axioms bsdfs_sound`: only `propext`, `Quot.sound`.
- `bsdfs_complete_once` (WF, s ≠ t): every such path is output exactly once (`count = 1`). **Proved** in `Bsdfs/Complete.lean` (with `Bsdfs/Paths.lean`, `Bsdfs/Cascade.lean`; statement unchanged, removed from `BsdfsExec.lean`); `#print axioms bsdfs_complete_once`: `propext`, `Classical.choice`, `Quot.sound` (choice from classical case splits; no `sorryAx`).
- `bsdfs_worst_case_delay` (WF, s ≠ t, 0 < k): step stamps of consecutive observable events (start, outputs, term) differ by at most 2k(n+m) (v3, changes_v3.md; 3(k+1)(n+m) in v2, 2(k+1)(n+m) patched). **Proved** in `Bsdfs/WorstCase.lean` (removed from `BsdfsExec.lean`; the assumption k ≤ n of the restated statement is not needed and was dropped); `#print axioms`: `propext`, `Classical.choice`, `Quot.sound`, checked by `#guard_msgs` in `Main.lean`.
- `bsdfs_amortized_delay` (WF, s ≠ t): the stamp of the τ-th observable event is at most τ(k+2)(n+m) (v3, needs the early exit at s; 2τ(k+1)(n+m) in v2). **Proved** in `Bsdfs/Amortized.lean` (removed from `BsdfsExec.lean`; the assumptions 0 < k ≤ n of the restated statement are not needed and were dropped); `#print axioms`: `propext`, `Classical.choice`, `Quot.sound`, checked by `#guard_msgs` in `Main.lean`.

## `bsdfs_sound`: how it went (Claude Code session, 2026-10-12)
Hoare triples over `StateM (St n)` with `mvcgen` (Std.Do, ships with Lean core), as planned; about 170 lines, builds in about 2 s.
- `fruitful_frame`: `fruitful` leaves `S` and `outputs` of the trace unchanged. `mvcgen` with the same frame invariant for both loops, then one `simp_all`. No reasoning about `List.range n` or `break` was needed.
- `search_sound`: precondition `st.S = S0`, `StackPath (S0 ++ [v])` (head s, Nodup, t ∉, zip/tail edges in G), `|S0| = h`, `h ≤ k`, outputs sound; postcondition `st.S = S0`, outputs sound. The theorem is itself recursive with `termination_by k - h`, mirroring `search`; the spec of the recursive call is passed to `mvcgen` like any other spec, and the case h ≥ k is vacuous (precondition `h + 1 ≤ k` false).
- What `mvcgen` did by itself: instantiated the ghost variable `S0` at the recursive call and at `fruitful`, kept the guard `b[w] + h < k` in context, supplied `w ∈ succ v` from the loop cursor (`succ v = pref ++ cur :: suff`), so the `for` loop needed no change. 3 of the 6 VCs of `search` needed manual proofs (output event, recursive-call precondition, outputs after `fruitful`); the rest are closed by `simp_all`.
- Friction: (1) the manual VCs are addressed by `mvcgen` case tags such as `vc1.step.isTrue.isTrue`, which change with the code and with the proof structure (switching from `induction` to `termination_by` renamed `vc7.ind.…` to `vc7.…`); (2) `mvcgen` is marked experimental in 4.34.1 (warning switched off with `set_option mvcgen.warning false`); (3) the zip/tail edge form of `BoundedPath` needed one induction lemma (`mem_zip_tail_snoc`).
- With the early exit at s the soundness proof compiled unchanged (same case tags).

## `bsdfs_complete_once`: how it went (Claude Code session, 2026-10-12)
The joint induction of `sec45/sec45_rewrite.tex` (Call Completeness, Search Preserves), about 1100 lines in three files, whole build about 5 s.
- `Paths.lean`: walks as an inductive `Graph.Walk X t x l` (nodes after x avoid X); `dist_X(y, t) ≤ L` is `WalkLE`, no distances as numbers. Edge-consistency `EC`, Barrier Distance Bound (`EC.walk_bound`), Pruning is Permissive (`pruning_permissive`), and a shortcut lemma from walks to simple paths (`Graph.Walk.path`).
- `Cascade.lean`: `fruitful_spec` via a BFS invariant: every enqueued node keeps its value and is enqueued once, queue values are sorted and within d + 1 of the pair being processed, and every processed pair (q, d) leaves its off-stack predecessors at most d + 1. Update Repairs follows from that without lem:cascade-distance (no exact distances needed), and every cascade write is witnessed by a walk avoiding the stack (lem:update-distance-bound).
- `Complete.lean`: one spec `search_spec` (recursive, `termination_by k - h`) with `SearchPost`: outputs Nodup and with prefix S0 ++ [v], Call Completeness, Return Value (min suffix length, or k + 1), the final write, stack barriers fixed, b[t] = 0, `mon` (a barrier drops only to a value ≥ dist_{S0}(y, t); this replaces the persistence argument of case (III)), Fruitless Monotonicity, and EC at exit for h > 0 (the early exit at s breaks it at h = 0, where it is not needed). The loop invariant `LoopInv` adds two clauses for case (III): `close` (fruitful) and the last clause of `fruitless`. Strict Barrier Invariant (`LoopInv.strict`) uses Call Completeness and the shortcut lemma. No-duplicate output: outputs of different successors differ at position h + 1 (needs `succ_nodup`); `rev` of `Graph.WF` is used in the cascade.
- Friction: (1) `mvcgen` instantiates ghost variables of a spec only when their equations come first in the precondition (`st.b = b0 ∧ … ∧ st.S = S0.push v`, not `st.S = S0.push v ∧ st.b = b0`); otherwise it silently fills them with whatever variables of the right type are in scope (here the outer `S0 b0 O0`) and leaves unprovable VCs; (2) the spec list of `mvcgen` takes names only (`have hcasc := fruitful_spec G hG t v S0` first); (3) an inner-loop invariant that mentions the outer loop's variables needs the case-label form `| inv2 _ cur _ _ qo hcur _ _ _ _ => …`, which names inaccessible hypotheses by position; (4) `b[x]` (Fin index) and `b[↑x]` (Nat index) are different atoms for `omega`, normalize with `simp only [Fin.getElem_fin]`; `rw` fails under `b[queue[j].1]` (dependent index proof), `simp only` works; (5) VCs are again addressed by case tags.

## `bsdfs_worst_case_delay`: how it went (Claude Code session, 2026-10-12)
Staged, about 3600 lines in nine files on top of the completeness proof. No change to the executable (smoke test re-run: identical).
- Stage 1, `Tally.lean`: the step counter equals the cost of the events so far (entry 1 + |succ|, dequeue 1 + |pred|, output |path|); between two observable events the stamps differ by the cost of the events in between plus the scans still owed by the frames open at the first one (`tally`).
- Trace model, `Trace.lean`: positions are indices into the event list; `stk tr p` and `bar tr p z` replay enters/exits and writes up to p; frames `Frame tr e x` (enter at e, exit at x, stack larger in between), counting `cnt` over position ranges. Phases without lookahead: for consecutive observable events a < c, m is the least stack size on (a, c], β the first position after which the stack has size m; descent (a, β], ascent (β, c] (m is the paper's j + 1).
- Stage 2, `DelayFacts.lean`, `DelaySum.lean`: the v3 counting (Drop Depth, Descent Split, per-node and per-edge budgets of edge_budget.tex and visits.md, t's empty slot absorbing the output) from an explicit structure `DelayFacts` (single-event facts, Per-Call Global Monotonicity, scans, and the v2 phase lemmas per interval); `worst_case_of_facts`.
- Stage 3b, `Phases.lean`: the v2 phase lemmas (Ascent Purity, Call–Phase Correspondence, Descent Origins, Dequeue Count, Descent Seal, One Entry per Pair per Phase) from `RunFacts`, facts about single events and single frames. Descent Seal follows the paper (witness walk, shortcut, Call Completeness), but its last step is simpler in the stack model: the frame that would output the constructed path is entered in the descent, so by Call–Phase Correspondence it returns inside the descent, where no output lies.
- Stage 3c, `RunTrace.lean`, `RunCasc.lean`, `RunSearch.lean`, `WorstCase.lean`: `RunFacts` from facts at single positions (`PosOK` = `EvOK` for the event, `CallOK` for the call entered there, `CascAt` for the cascade it belongs to); these refer only to positions up to the exit of the call or cascade involved, so they survive appending events. Hoare specs `fruitful_spec_tr` and `search_spec_tr` extend `fruitful_spec` and `search_spec` (same `mvcgen` case tags, the old step lemmas reused) with trace invariants `TrCasc` and `TrLoop`/`TrCall`; correspondence of the state with the replay (`stk`, `bar` at the end of the trace), stack prefix while the frame is open, the scan position of each successor.
- Friction: (1) `simp` normalizes `(T ++ [c] ++ [w])[q]?` before using a hypothesis about it; small lemmas over a variable trace (`Trace.dropAt_none`, `dropAt_ne`, `isCasc_enter`, ...) applied with `rw` avoid that; (2) bash heredocs choke on Lean primes, so Lean text goes through files.

## `bsdfs_amortized_delay`: how it went (Claude Code session, 2026-10-12)
`Amortized.lean`, about 700 lines, on top of the worst-case files; no new Hoare spec was needed.
- Accounting: the stamp of an observable event c is at most the cost of the positions (0, c] (`bsdfs_stamps`), the start costs nothing and nothing is owed there. With the periods (β_{τ-1}, β_τ] (ascent of interval τ-1, descent of interval τ, β from the interval shapes of `DelaySum.lean`): cost (0, β_τ] ≤ τ(k+2)(n+m) by induction over the observable events (`cost_to_beta`), plus the ascent (β_τ, o_{τ+1}] ≤ (k+2)(n+m) (`asc_cost`, from `Ea_le`). A list lemma (`filterMap_le`) turns the per-position bound with the number of earlier observable events into the statement about `obsSteps[τ]`.
- Period Budget (`node_period`, `edge_period`): entries in a period split into those still open at the output o_τ (at most one per node, as the stack has no duplicates) and the rest, which are fruitless, return within the period with their raise, and have pairwise distinct depths (`nR_inj`: a second call at the same depth needs a drop in between, excluded in the ascent by Ascent Purity and in the descent by Descent Seal). Depths ≥ 1, as the root call is open at o_τ; ≥ i + 1 by Period Split when the node or a successor is dropped first by an origin at depth i; dequeues ≤ drops + 1 ≤ i + 1 (`U_le`, Dequeue Count).
- Period Split (`period_split`), as in edge_budget.tex: the descent by Descent Split; ascent calls nested in the origin's frame by depth; ascent calls before the origin's entry e₀ bring b[y] to ≥ k − h before e₀ (raise at y, a fruitless child at y, the failed guard, or a fruitless frame of y on the stack), b[y] does not decrease up to e₀, and b[y] at e₀ is at most the drop value (Per-Call Global Monotonicity of the origin's frame). That a frame exiting in the ascent is fruitless follows from the interval shape (one open at the previous output would be open at β + 1 above the minimum depth).
- Extra facts about the run beyond `RunFacts` (`AmortFacts`): the start event at position 0, the root frame (1, x), and the term event at x + 1 as the last event; read off the root call's `TrCall`.
